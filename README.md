# SheetDock

現在のソースは **1.2.0（正式リリース準備中）** です。CSV・XLSXの並べ替え・フィルターを本体へ接続しました。公開済みの安定版は1.1.0（CSV・TSV・XLSX対応）、1.0.0はCSV専用です。

XLSXでは型を保つ直接セル編集、シートタブ、条件付きの行列挿入・削除と末尾追加、行高・列幅のドラッグ／数値指定、Undo/Redo、検索・文字列置換、選択シートのCSV出力、安全な保存に対応します。数式セル・結合範囲の編集を制限し、未対応機能を検出したブックは読み取り専用にします。

対応範囲・制限と要件照合は[docs/Phase2_Review.md](docs/Phase2_Review.md)、実装経緯と機能別の確認手順は[docs/Phase2_Integration.md](docs/Phase2_Integration.md)、利用者向けの操作説明は[DISTRIBUTION_README.md](DISTRIBUTION_README.md)を参照してください。

## 開発環境での起動

Python 3.12とTkinterを使用します。SheetDockのルートで仮想環境を有効にして実行してください。

```powershell
python -m pip install -e ".[test]"
python -m pytest -q
python -m sheetdock
```

既に依存パッケージが導入済みならインストールは不要です。
pytestは既定で `tests` 内の本体テストのみを実行します。現在894件です。前版805件に、XLSX並べ替え・フィルターモデル45件と本体接続44件を追加しました。

## CSVの機能

- 複数CSVをタブで開く。同じパスを再度開いた場合は既存タブへ切り替える。
- CSVの読込。文字コードは自動／UTF-8／CP932、区切りはカンマ／タブ／セミコロン、見出しはあり／なしを選択。
- セル編集、既存表の範囲内でのコピー・貼り付け、複数行列の挿入削除、見出し編集。
- 全セル検索の次へ・前へ、1件置換、一括置換（見出しを含む、部分一致、大文字小文字を区別）。
- 編集エンジンが管理するUndo/Redoと、未保存データの破棄確認。
- 元の文字コード・BOM・レコード改行・区切り文字を原則維持した別名保存。一時ファイルの再読込一致を確認してから置換。

「保存」またはCtrl+Sで現在のファイルへ上書き保存します。「別名保存」は異なる保存先を選びます。「保存時にバックアップ」が有効なら、既存ファイルの保存時に1世代の `.bak` を作ります。初期値は有効です。世代管理は現在1世代のみです。
別名保存成功後は、そのタブのパス・ファイル名・保存済み状態を更新します。別のタブで開いている保存先への書込は拒否します。

## Phase 3：CSV・XLSX並べ替え・フィルター

CSVタブの「CSV 対象列」欄で列番号、文字列／数値、昇順／降順を指定して並べ替えます。見出しを除いた行全体と行高が移動し、1回でUndo/Redoできます。同値の順序を維持し、空セルは常に最後です。数値順もCSVの元の文字列・先頭ゼロを変更しません。

フィルターは1列の部分一致・完全一致・空・空以外です。表示だけを絞り、保存は常に非表示行を含む全行です。直接編集・コピー・切り取り・セル内容削除と、表示範囲内への長方形貼付けが使えます。フィルター中の貼付けは「貼り付け」ボタンまたはCtrl+Vを使い、範囲超過は全体を拒否します。

フィルター中は、並べ替え・行列挿入削除・検索置換・見出し切替編集・行高変更の前に解除します。フィルターはファイルタブ別に保持し、再読込・再起動時は解除します。設定JSON・CSVには条件を保存しません。XLSXの操作はシート内の「XLSX 対象列」欄で行います。型を維持して行全体を並べ替え、シート別に表示を絞ります。フィルター中もF2・ダブルクリックで本文を編集でき、保存・CSV出力は非表示行を含みます。先頭行を見出しにする指定は並べ替え・フィルターの対象を決めるものです。詳細は[DISTRIBUTION_README.md](DISTRIBUTION_README.md)を参照してください。

8. ウィンドウを閉じる際、未保存タブごとに確認が出ることを確認する。途中でキャンセルした場合、タブを削除せず画面へ戻ることを確認する（それまでに成功した保存は維持する）。
9. 最後のタブを閉じてから新しくCSVを開けることを確認する。

タブごとに独立した表ウィジェットを持ち、通常のタブ切替では選択と列幅も維持します。ただし構造変更・Undo/Redoによる再表示では選択がリセットされる場合があります。全タブの表・履歴をメモリに保持するため、大容量対応は後続の検証対象です。

## 上書き保存・外部変更のWindows確認

テスト用にサンプルCSVをコピーして使用してください。

1. CSVを開いてセルを編集し、「保存」またはCtrl+Sを実行する。タブの「*」が消え、元ファイルと同じフォルダーに `ファイル名.csv.bak` ができることを確認する。
2. CSVをSheetDockで開いたまま、メモ帳でも同じファイルを開き、IDなどを変更して保存する。SheetDock側でも別の値に編集する。
3. SheetDockで保存し、「外部変更を検出」でキャンセルする。外部のファイルも、SheetDockの編集も残ることを確認する。
4. 再度保存し、「いいえ：再読込」を選ぶ。未保存編集の破棄確認で「いいえ」を選ぶと、編集が残ることを確認する。
5. 再読込と破棄確認の両方を承認する。メモ帳で保存した値に変わり、「*」が消え、以前の編集をUndoできないことを確認する。閉じる操作の途中で再読込した場合は、確認のためタブを残す。
6. 再びSheetDockとメモ帳で異なる編集をし、保存時に「はい：上書き」を選ぶ。SheetDockの内容で保存され、`.bak` に外部で更新した直前の内容が残ることを確認する。
7. 通常の別名保存と、未保存タブを閉じるときの保存・破棄・キャンセルも確認する。

再読込の文字コード・区切りは現在のタブの設定を使います。外部で文字コードまで変更された場合は読込エラーになることがあり、その場合は元の編集を残します。

## 保存の競合対策と限界

読込時と保存前の更新日時・サイズ・SHA-256を比較します。保存処理では、一時ファイルの再読込検証後とバックアップ作成後にも比較します。外部変更を検出した場合は上書き・再読込・キャンセルを選択できます。保存失敗時は未保存状態を維持します。

同じ保存先へのSheetDock同士の保存をロックファイルで抑止します。別のアプリはこのロックを利用しないため、最終確認とファイル置換の間に外部アプリが書き込む競合を完全には防げません。電源断・ディスク障害への完全な耐性も保証しません。

通常、ロックファイルは成功・失敗どちらでも削除します。強制終了などで `.ファイル名.sheetdock-save.lock` が残った場合は自動削除せず保存を止めます。そのCSVを保存中のSheetDockがないことを確認してから、残ったロックだけを削除してください。データファイルや `.bak` は削除しないでください。

バックアップ有効時は、外部変更時の上書きで外部の最新内容を1世代のバックアップとして残します。CSVが削除された場合に上書きを承認すると再作成します。バックアップ先が別タブで開かれている場合は保存を止めます。バックアップの有効・無効は画面のチェックで切り替えられます。

## 文字コードの自動判定と手動再読込

文字コードの初期値は「自動」です。BOMありUTF-8はUTF-8として読み込み、BOMなしはUTF-8・CP932で厳密に復号します。候補が1つなら採用し、両方で読めて表示内容が異なる場合はプレビュー付きの選択画面を出します。ASCIIだけなど表示内容が同じならUTF-8を使います。元の文字コード名を必ず特定できる方式ではありません。対応候補はUTF-8とCP932で、UTF-16/UTF-32のBOMやNULを含むファイルは自動読込の対象外です。

判定に外部ライブラリは追加していません。不正な文字を置換して読込を続けることはせず、選択取消や読込失敗時は既存のタブ・編集を維持します。プレビューは先頭1200文字です。

上部でutf-8またはcp932を選べば、次に開くCSVをその文字コードで読み込みます。開いているタブの文字コードを見直す場合は、上部で希望する文字コードを選び、「文字コードで再読込」を押します。未保存の編集がある場合は破棄確認を行い、読込成功後にデータとUndo履歴を入れ替えます。再読込失敗や文字コード選択のキャンセルでは入れ替えません。

保存形式はタブごとに保持します。上部の選択だけでは、既に開いているタブの保存文字コードは変わりません。現在の文字コード・BOM・改行形式は画面下部で確認できます。

### Windows確認

1. 文字コードを「自動」にし、既存サンプルのutf8_bom_crlf.csv、utf8_lf.csv、cp932_crlf.csvを順に開く。選択画面が出た場合は正しい日本語に見える候補を選ぶ。
2. 開いたタブの画面下部で文字コード・BOMを確認する。編集・保存・開き直しで日本語と00123が保持されることを確認する。
3. 新しい `probes/samples/encoding_ambiguous_utf8.csv` を「自動」で開く。候補プレビューが出て、utf-8を選ぶと「表」「名前」が正しく表示されることを確認する。
4. 同じファイルの選択画面をキャンセルする。新規タブを追加せず、既存タブと編集内容が残ることを確認する。同じファイルを既に開いている場合は重複を避けて既存タブへ切り替えるため、選択画面の確認前にそのタブを閉じる。
5. 曖昧なサンプルをcp932の手動指定で開く。上部をutf-8へ変更して「文字コードで再読込」を押すと、表示が正しい日本語へ変わることを確認する。
6. CP932のサンプルを編集後、utf-8を指定して「文字コードで再読込」を押す。破棄確認を承認しても読込が失敗した場合は、元の編集内容とUndo履歴が残ることを確認する。
7. 新しいascii_only.csvを「自動」で開く。候補選択なしで開き、00123が文字列として保持されることを確認する。

UTF-8 BOMなしでもCP932で復号できる日本語は多いため、UTF-8のファイルでも選択画面が出るのは想定動作です。

保存完了後も、画面下部にはファイルパス・文字コード・BOM・改行形式・未保存状態を表示します（上書き保存・別名保存とも共通）。

## 開いた後の見出し行の切替

「現在のタブの先頭行を見出しにする」で、現在のタブの表示を切り替えます。上部の「次に開くCSV」にある見出し指定は、新しく開くファイルの初期表示だけに適用します。

表示の切替はセルデータを書き換えません。先頭行のデータ・保存形式・Undo/Redo履歴を保持し、切替だけでは未保存になりません。セル編集中に切り替えた場合は、そのセル編集を確定してから表示を切り替えます。各タブの表示モードは独立しています。切替時は表を再表示するため、選択位置がリセットされる場合があります。列幅は保持します。見出し表示モードの再起動後の記憶は現在の設定保存の対象に含めていません。

### Windows確認

1. 見出しありでCSVを開き、新しいチェックをオフにする。見出しが本文の先頭行に現れ、オンに戻すと見出しへ戻ることを確認する。
2. 切替だけではタブに「*」が付かず、先頭行や00123が変わらないことを確認する。
3. 見出しを通常セルとして表示して編集し、見出し表示へ戻す。変更が反映され、Undo/Redoでその編集を戻せることを確認する。
4. 本文のセルを編集中に切り替える。編集値が消えず、Undoで戻せることを確認する。
5. 2つのタブを開き、一方だけ切り替える。他方の表示・データ・履歴が変わらず、戻ったときにチェック状態が正しいことを確認する。
6. 切替後に保存して開き直す。先頭行が消えたり、二重に追加されたりしないことを確認する。
7. 最後のタブを閉じると切替チェックが無効になり、新しく開くと使えることを確認する。

## 検索・置換

「検索」または「一括置換」ボタンで共通の検索・置換画面を開きます。「次へ」「前へ」で一致箇所を順に選択し、端まで来ると折り返します。同じセルの中に複数の一致がある場合も、1箇所ずつ数えます。画面には一致番号、行列位置、セル内の文字位置を表示します。表ではセル単位で選択し、セル内の部分文字列自体は強調表示しません。

「1件置換」は現在の一致箇所だけを置換して、次の一致へ移動します。検索前に押した場合は最初の一致を置換します。「すべて置換」は現在のタブ全体（見出しを含む）を対象とします。空の置換後文字列は削除として使えます。いずれも各操作をUndo/Redoで戻せます。

検索画面を開いたままタブを切り替えた場合、次の検索・置換操作は切替後のタブへ適用します。位置管理はタブごとに独立しています。表を編集・Undo/Redoした後は古い一致箇所による置換を止め、もう一度検索するよう案内します。

### Windows確認

1. CSVの本文セルへ「確認確認」、別の本文セルへ「確認」を入力する。検索画面を開き、検索文字列に「確認」を入力する。
2. 「次へ」で3箇所を順に移動し、最後から先頭へ戻ることを確認する。「前へ」でも逆順・折り返しを確認する。同じセルでも一致番号・文字位置が変わることを確認する。
3. 置換後を「済」にし、「1件置換」で1つだけ変わることを確認する。Undo/Redoでその1件を戻せることを確認する。
4. 「すべて置換」で残りが置換され、Undo1回で一括置換前に戻ることを確認する。
5. 見出しの文字列でも検索できることを確認する。一致箇所が見出しなら結果表示に「見出し」と出る。
6. 検索後に表の別のセルを編集し、「1件置換」を押す。再検索の案内が出て、余分な置換が起きないことを確認する。「次へ」で検索し直すと置換できる。
7. 検索画面を開いたままタブを切り替え、検索・置換が切替後のファイルへ適用され、他のタブのデータと履歴が変わらないことを確認する。

検索は大文字小文字を区別する部分一致です。正規表現や重なり合う一致は扱いません。例えば「aaa」から「aa」を検索すると1箇所として扱い、一括置換と同じ規則を使います。

## 設定保存

保存先は `%LOCALAPPDATA%\SheetDock\settings.json` です。
編集中のセルデータは設定JSONに保存しません。

- 「保存時にバックアップ」の変更をその場で保存します。初期値は有効。無効にしても既存の `.bak` は削除しません。
- ファイルを正常に開いた時と別名保存に成功した時に履歴を更新します。直近10件を「ファイル → 最近使ったファイル」で表示します。同じパスは重複させず先頭へ移します。削除・移動されたファイルは履歴に残し、開こうとした時にエラーを表示します。
- 通常終了時にウィンドウ位置・サイズを保存します。最大化・最小化している場合は直前の通常表示の配置を保存します。次回起動ではプライマリ画面内へ補正して復元します。最大化状態そのものは今回の対象外です。
- 複数起動時は最新の設定に変更項目だけを反映します。保存は一時ファイルへの書込と置換、保存ロックを使います。
- 設定が読めない・形式が壊れている場合は初期値で起動して案内を表示します。設定変更時に正常な形式へ保存します。
- 列幅もファイルごとに保存します。履歴には現在パスのみを保存し、履歴から開く時は画面上部の読込条件を使います。

### Windows確認

1. ウィンドウを移動・サイズ変更して終了する。再起動すると位置とサイズが復元されることを確認する。
2. 「保存時にバックアップ」をオフにして終了・再起動し、オフが維持されることを確認する。
3. まだ `.bak` がないテスト用CSVを開いて編集・上書き保存する。オフなら `.bak` を作らず、オンに切り替えて再び編集・保存すると `.bak` を作ることを確認する。
4. 複数のCSVを開いて終了・再起動する。「ファイル → 最近使ったファイル」に履歴が残り、メニューから開けることを確認する。同じファイルを開くと先頭へ移り、履歴は増殖しない。
5. 11個以上のテスト用ファイルを開き、履歴が直近10件になることを確認する。
6. 別名保存に成功した保存先も履歴に載ることを確認する。
7. 保存先フォルダーにsettings.jsonが作られ、セルの内容が入っていないことを確認する。

設定保存に失敗しても編集中データは保持します。バックアップ設定の保存が失敗した場合は、チェックを変更前へ戻してエラーを表示します。

### ウィンドウ位置の修正

初期レイアウトが終わるまで本体ウィンドウを非表示にし、保存済みの位置・サイズを適用してから表示します。初回のConfigureイベントでは保存配置を更新しません。保存配置がない・無効な場合は、プライマリ画面中央へ表示します。終了時もレイアウトを確定してから通常表示の配置を保存します。

Windowsで、位置・サイズを変更して通常終了し、再起動して同じ配置に戻ることを確認してください。既存のバックアップ設定と履歴はそのまま使います。初回表示の中央配置を試す場合は、SheetDockを閉じた状態でsettings.jsonのwindow_geometryだけをnullにしてから起動すると、他の設定を保持して確認できます。

## サブ画面の配置

検索・置換、文字コード選択、行列挿入や見出し編集の入力画面、確認・エラー画面は、初回は親画面の中央に表示します。移動・サイズ変更して閉じると、その種類の画面の前回配置をsettings.jsonのdialog_geometryへ保存し、次回から復元します。画面外へ出る配置はプライマリ画面内へ補正します。検索画面を開いたまま本体を終了した場合も位置を保存します。

入力・確認画面は配置を制御できるTkinterの画面に統一しました。はい・いいえ・キャンセルの意味は維持しています。入力のキャンセルや閉じる操作では値を適用しません。入力・検索の文字列自体は設定へ保存しません。

Windows標準の「開く」「名前を付けて保存」はOS側の画面のため、この保存・復元の対象外です。

### Windows確認

1. 親画面を移動してから、検索・置換画面を初めて開き、親の中央に表示されることを確認する。
2. 検索画面を移動・サイズ変更して閉じ、再度開く。前回の配置になることを確認する。本体を再起動しても復元されることを確認する。
3. 行・列挿入、見出し編集の入力画面も、初回は親中央、移動して閉じた後は前回の配置になることを確認する。
4. 未保存タブを閉じる確認などでも中央表示・移動後の復元ができ、はい・いいえ・キャンセルの動作が変わらないことを確認する。
5. 曖昧な文字コードのサンプルを開き、選択画面の中央表示と前回位置の復元を確認する。同じファイルのタブが開いている場合は一度閉じてから試す。
6. 親画面の位置・サイズ、バックアップ設定、最近使ったファイルも維持されることを確認する。

画面の種類ごとに配置を記憶するため、親画面を移動しても、記憶済みのサブ画面は前回の画面上の位置を優先します。配置の保存が失敗した場合も、入力や確認の操作結果はそのまま適用します。

## ファイルごとの列幅

列見出しの境界をドラッグして変更した幅を、settings.jsonのfile_widthsへパスごとに保存します。列幅の変更だけではCSVの未保存状態になりません。タブ切替・見出し切替・再読込・再起動後に幅を維持または復元します。別名保存に成功した場合は新しいパスにも幅を保存します。

列挿入では新しい列を120ピクセルとし、後ろの列の幅を移動します。列削除では対応する幅も削除します。列構造のUndo/Redoでは対応する幅も復元します。セル編集のUndo/Redoでは列幅を変更しません。

CSVが未保存状態の間は、現在の列幅をメモリで保持し、CSVの保存成功後に設定へ反映します。未保存の列構造を破棄した場合は、その構造の幅を元ファイルの設定に書き込まないためです。再読込時は保存済みのファイルの幅を読み直します。

外部で列数が変わっていた場合は、保存済みの幅を列順に使い、不足分を120ピクセルとします。設定の幅が不正な場合も既定幅へ戻します。パスが変わるファイル移動は別ファイルとして扱います。入力データ・セル内容は幅設定へ保存しません。

### Windows確認

1. CSVを開き、複数の列を異なる幅へ変更する。タブに「*」が付かないことを確認する。
2. 2つのCSVを異なる幅にし、タブ切替・見出し切替で各ファイルの幅が保持されることを確認する。
3. 本体を終了・再起動して同じCSVを開く。各ファイルの列幅が復元されることを確認する。
4. 「文字コードで再読込」を実行し、幅が復元されることを確認する（未保存編集を破棄した場合は保存済みの幅へ戻る）。
5. 途中へ列を挿入・削除し、元の列の幅が対応して移動することを確認する。Undo/Redoで列と幅が一緒に戻ることを確認する。
6. 列構造を変更してCSV保存する。再起動して開くと保存後の構造と幅が復元されることを確認する。
7. 別名保存後、そのファイルを開き直して幅が復元されることを確認する。

## エラー・警告ログ

ログの保存先は `%LOCALAPPDATA%\SheetDock\logs` です。起動プロセスごとに `sheetdock-プロセスID.log` を作り、複数起動時の書込先を分けます。各プロセスのログは512KiBでローテーションし、過去2ファイルまで残します（.log.1、.log.2）。異なるプロセスIDのログは別に残るため、フォルダー全体のファイル数が3つに限定されるものではありません。

記録するものは日時、ERROR/WARNING、固定の処理名、エラー型、OSエラー番号です。セル内容・検索語・置換文字列・ファイルパス・例外本文・スタックトレースはログへ記録しません。

主な処理名：read（読込）、save（保存）、reload（再読込）、edit（編集）、search（検索・置換）、external_change（外部変更検出）、settings_read/settings_save（設定）、geometry_save/dialog_geometry_save（配置）、widths_save（列幅）、recent_save（履歴）、gui_callback（未処理のGUI例外）。

ログを作成できない場合は起動時に案内し、ログなしで続行します。起動後のログ書込失敗も編集を止めません。正常な読込・保存の成功は記録しないため、エラーがなければログが空の場合があります。

### Windows確認

1. 本体を起動し、logsフォルダーとsheetdock-数字.logが作られることを確認する。
2. 文字コードをutf-8に指定してcp932_crlf.csvを開き、読込エラーを出す。ログにoperation=read、error=UnicodeDecodeErrorが記録されることを確認する。
3. ログにセル内容・CSVファイルのパス・例外本文が含まれないことを確認する。
4. 正しい文字コードで開き直し、通常の編集・保存ができることを確認する。
5. 2つのSheetDockを起動してそれぞれ読込エラーを出し、別のプロセスIDのログが作られることを確認する。

ログにはパスを残さないため、問題報告時には操作手順と画面のエラー表示も併せて確認してください。ファイル内容を丸ごと共有する必要はありません。

## 大容量CSVの警告

ファイルサイズ5MiB以上は、CSVの読込前に読込・中止を選択します。それ未満でも、初期のCSV解析で10万セル以上と判明した場合は、編集モデル・表画面を作る前に表示・中止を選択します。サイズ警告を承認した場合はセル数の警告を重ねません。新規オープン、履歴からのオープン、再読込に適用します。既に開いているファイルへのタブ切替には再警告しません。

警告は読込禁止の上限ではありません。「いいえ」または確認画面を閉じると読み込みを中止し、既存タブと未保存編集を保持します。通常のファイルは警告なしで開きます。ログにはlarge_file／large_tableの警告名だけを残します。

### 基準を決めるための測定

Python 3.12.14／Linux。UTF-8 BOMあり、10列の合成CSVで、読込・Session作成・表示用データコピー・1回のセル編集を測定しました。

| 行数（見出し含む） | サイズ | 測定時間 | Python割当のピーク |
| --- | --- | --- | --- |
| 1,001 | 約0.26MiB | 0.428秒 | 2.21MiB |
| 10,001 | 約2.58MiB | 3.940秒 | 21.96MiB |
| 50,001 | 約12.92MiB | 18.807秒 | 109.73MiB |

tracemallocによる測定のオーバーヘッドを含みます。これはTk描画・Windows実機・プロセス全体のメモリを測った値ではありません。文字列の長さやセル数によって負荷は変わります。初期の警告基準は保守的に5MiB／10万セルとし、Windowsの実測に応じて調整します。

同じ合成CSVを一時フォルダーで測りたい場合は、次を実行できます。手元のCSVは変更せず、測定用CSVは終了時に削除します。

```powershell
python -m sheetdock.benchmark
```

### Windows確認

1. 小さい既存サンプルを開き、警告が出ないことを確認する。
2. 未保存の編集があるタブを残して、probes/samples/large_size_warning.csvを開く。読込前にサイズ警告が出て、「いいえ」で既存の編集が残り、新規タブが増えないことを確認する。
3. 同じサンプルで「はい」を選ぶ。読み込めて、セル数警告が重ならないことを確認する。読み込みに時間がかかる場合は完了を待つ。
4. probes/samples/many_cells_warning.csvを開く。サイズは小さいが10万セルを超えるため、表の表示前にセル数警告が出ることを確認する。いいえなら中止、はいなら開くことを確認する。
5. 警告を承認して開いたタブでも、通常の編集・Undo/Redo・保存ができることを確認する。

表示用モデルを作る前の警告では、初期のCSV解析自体のメモリは既に使っています。非同期読込・読込途中のキャンセル・大容量向けの履歴メモリ制限は今回の対象に含めていません。
