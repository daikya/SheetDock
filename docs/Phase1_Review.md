## 判定

Phase 1の主要機能は実装され、段階ごとのWindows確認が完了している。正式配布の完了とは区別し、以下の最終確認と配布準備を終えてからリリース判定する。

- Windowsで実際の保存失敗を起こし、ファイルと編集中データが残ることを確認する。例外を注入した自動テストは成功している。
- exe化、exeでの実機確認、配布ZIP、ライセンス文書、リリースVersionを用意する。

## 現在の明示的な制限

1. 文字コード候補はUTF-8とCP932、区切り文字はカンマ・タブ・セミコロン。UTF-16/32の自動読込は対象外。
2. 混在レコード改行を含むCSVは拒否する。元の引用スタイル・末尾改行の有無を含むバイト一致は保証しない。セルの値と保存形式の一致を検証する。
3. 範囲貼付けは既存表の範囲内。追加が必要な場合は先に行列を挿入する。新規の空CSVを作る画面は現在ない（38項目に新規作成の明示要件はない）。
4. 履歴は表全体のスナップショット。大容量でのメモリ制限・非同期読込・読込途中の取消は未実装。警告承認後の読込を保証するサイズ上限は定めていない。
5. セル数警告は最初のCSV解析後、編集モデルと表画面の作成前に出す。解析分のメモリは既に使用する。
6. 外部アプリはSheetDockの保存ロックに従わないため、最終確認と置換の間の競合を完全には防げない。電源断・ディスク障害への完全な耐性は保証しない。
7. バックアップは1世代。CSVと.bakは別々の保存結果であり、完全なトランザクションではない。異常終了で保存ロックが残った場合の扱いはREADMEに記載。
8. ウィンドウ配置はプライマリ画面内へ補正する。最大化状態そのものは保存しない。Windows標準のファイル選択画面はOSが配置を管理する。
9. 見出しの表示モード・最近使ったファイルの読込条件は再起動後に記憶しない。履歴から開く時は画面上部の読込条件を使う。
10. Excel編集・並べ替え・フィルターは今回のPhase 1配布対象外。

上記は新しい確定要件ではなく、現在の実装境界である。機能を増やす場合は要件への影響を確認して段階的に扱う。

## 配布前に行う2つの実機最終確認

### A. Excelとの相互コピー

- 本体の表内に十分な行列を用意し、2行以上・2列以上の範囲をExcelと相互コピーする。
- 日本語、空セル、引用符、タブ、セル内改行を含め、セルの境界が崩れないことを確認する。
- 00123の確認では、Excel側を文字列書式にする。Excel側の自動数値変換とSheetDock側の文字列保持を区別する。
- SheetDock側の貼付けをUndo1回で戻し、Redoで再適用できることを確認する。

### B. 保存失敗時のデータ保護

- テスト用CSVのコピーで行う。個人データや実運用ファイルは使わない。
- Windowsで別プロセスが対象CSVを排他的に開いた状態を作り、SheetDockの保存を実行する。メモ帳で開くだけでは排他ロックになるとは限らない。
- エラーが表示され、元CSVの内容、SheetDockの未保存編集、Undo履歴が残ることを確認する。
- 排他状態を解除してから保存すると成功することを確認する。

## 配布準備の現状と次工程

- 現行Versionは0.1.0.dev0。正式Versionは配布準備段階で確定する。
- 実行時依存はtksheet==7.6.0。ローカルの配布メタデータのLicense-ExpressionはMIT。その他の同梱物は実際のビルド内容で棚卸しする。
- 本体のLICENSE、THIRD_PARTY_NOTICES.md、exeビルド処理、配布ZIP作成処理は未作成。本体ライセンスはまだ確定していない。
- exeには検証用コード・テスト・合成CSV・ユーザーのCSV・settings.json・ログを同梱しない。本体、必要な依存、配布README、必要なライセンス情報を対象にする。
- ソース版の最終確認 → ライセンス・正式Versionの確定 → Windows exeビルド → exe版で主要操作確認 → 配布ZIP確認 → GitHub Release、の順で進める。
- probesと検証時READMEの整理は、ソース版最終確認後に行う。ユーザーが作ったCSVやテスト出力ファイルを一括削除しない。

## 結論

Phase 1の主要機能の確認はそろっている。最終版でのExcel相互コピーと実際の保存失敗の確認を行い、配布準備へ進む。Phase 2/3の機能が未実装であることは、Phase 1配布を妨げる未対応項目として扱わない。
